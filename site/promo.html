Best practices from AI Engineer talks, and how Harness Firmware does them

0:00 / 5:00

The quotes and where they come from

Each quote is an excerpt copied from a talk’s captions and links to the moment it was said. The talks cover building with AI agents in general; no speaker reviewed or endorsed Harness Firmware. Beside each quote is how Harness Firmware does it.

  1. “Define your guardrails, your agents, your docs, testing policies, really governance just one time”
    Davis Palmie, Factory · The Software Factory: From Bug Report to Production Code, 11:48

    The template’s CLAUDE.md comes with working rules switched on, such as checking logs, scripts and code before calling anything done, and flagging the risk when the deciding check was not run. When you ask for setup, /init-project reads your repository and fills in the kernel’s sections on which signal shows a change works and how deploys happen, and asks you about the facts it needs and does not find.

  2. “We just progressively disclose what’s in the context and what tools to use.”
    Tereza Tížková, Factory · What It Actually Takes to Build a Software Factory, 16:14

    The template ships the project memory already split: CLAUDE.md stays short and holds the rules that apply everywhere, and topic detail lives in files under .claude/reference/. /recall reads the file a task needs, and the kernel’s own rules favor pruning stale lines over adding new ones, so less is loaded on every turn.

  3. “When you join a new company there are a lot of rules that are not really codified anywhere.”
    Tereza Tížková, Factory · What It Actually Takes to Build a Software Factory, 19:29

    A rule in the template has the agent save a confirmed quirk, one that cost a retry, a backed-out change or a correction, to .claude/reference/pitfalls.md before the task ends, without being asked. The file is committed, so git carries it to every machine and sandbox, and when a saved fact changes what the agent does, /recall cites the file and its date.

  4. “It’s so difficult to catch up but also to predict what we’ll be winning. So it’s best to be agnostic”
    Tereza Tížková, Factory · What It Actually Takes to Build a Software Factory, 5:12

    Claude Code and Codex are both set up to read and write the same committed files in .claude/reference/, with each tool’s built-in memory turned off, so a lesson one tool saves is there for the other when you switch.

  5. “The danger is that the engineer never noticed that there was a choice to make.”
    Gabriel Martinez, G2i · Generation Is Cheap, Review Is Expensive: How to Stop Shipping AI Slop, 1:00

    /deep-plan keeps a ledger of each decision in your own words, with the options you turned down. Low-stakes guesses are listed as assumptions you can veto, and before you give the go-ahead a fresh reviewer with no memory of the conversation tests the weightiest decisions.

  6. “You will change your approach.”
    Matt Gibiec, Dynatrace · Your AI Agent Has No Nervous System, 2:06

    You start /long-horizon. Its state file keeps the approaches that failed audit, which are not retried without new evidence, and when the same step fails its audit twice the run has to take a new approach. Work that passed its audit stays in the verified list.

  7. “The agents will often overconfidently claim that they did something when in fact they did not do it.”
    Miguel (Browserbase) and Corby (Microsoft) · Your LLM Judge Is a Confident Liar: Building Better Verifiers, 6:50

    In /long-horizon each step’s checks are written before the step runs and saved with a recorded hash. A fresh auditor runs them without reading the worker’s report, a content hash of the workspace shows whether the worker touched the check it is graded by, and a final auditor reruns every check before the report.

  8. “Side-by-side comparison becomes the next evolution of the eval cycle”
    Hussein, Braintrust · Why Building an Eval Platform Is Harder Than It Looks, 9:52

    /arena builds three versions from different angles in separate worktrees. A fresh judge checks them against a short list of pass or fail criteria with their names hidden, the strongest becomes the base, and the best ideas from the others are grafted onto it.

  9. “Expensive things you want to run once when the PR goes up.”
    Dru Knox, Tessl · Harness Engineering: How to Build a Software Factory, 7:23

    When you type /merge, Codex reviewers check the pull request, confirmed findings are fixed, and the whole diff is reviewed again. It squash-merges at the commit that was reviewed once every CI check passes, and you can turn merge mode off at any time.

  10. “Find me all traces in the last 24 hours where the user had a poor experience.”
    Hussein, Braintrust · Why Building an Eval Platform Is Harder Than It Looks, 14:42

    /refine weekly reads the last seven days of Claude Code sessions on your machine in this repository, counts the times you corrected the agent or repeated an instruction, and compares that with its previous four runs. Edits that pass its evidence gate go into one pull request for you to review. It never merges, and you set up the schedule yourself.

No talk covered these

  1. Cross-company review

    Opening or updating a pull request starts a review by the other company’s model, switched on from the start: OpenAI’s Codex reviews pull requests made in Claude Code, and Anthropic’s Claude reviews pull requests made in Codex. Each finding is checked before anyone acts on it, and you merge the pull request or type /merge (Harness-Firmware #214).

  2. /coordinate

    /coordinate gives two chats a protocol for checking each other’s claims. The chat you run it in reads the pull request diff, its CI checks and main itself and gives a verdict on each numbered item. The other chat reviews that review and answers until both agree, and a point still open after two exchanges comes to you with both positions. A message from the other chat never counts as your approval, so a step that needs your go comes to you.

  3. Codex skill sync

    Each Claude skill either has a Codex port, translated by hand, or is switched off for Codex. A recorded hash of each ported Claude skill lets a check warn, on your machine and in CI, when a skill changed after its Codex port was last reviewed.
