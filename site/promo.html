What the talks recommend, and what Harness Firmware already does

0:00 / 2:00

The quotes and where they come from

Each quote is copied from the talk's captions and links to the moment it was said. The speakers recommend practices; none of them reviewed or endorsed Harness Firmware.

  1. “Because you only ever need to create it once it saves you the time from having to continuously reprompt.”
    Nick Saraev, YouTube educator · AI Harnesses Explained in 24 Minutes For Normal People, 6:24

    The kernel, CLAUDE.md for Claude Code and AGENTS.md for Codex, loads in every session, so project rules are written once.

  2. “We just progressively disclose what’s in the context and what tools to use.”
    Tereza Tížková, Factory · What It Actually Takes to Build a Software Factory, 16:14

    Each skill's name and description load every turn; its full playbook loads only when a task calls it.

  3. “If agents would try to figure out that from scratch, they are likely going to fail.”
    Rafal Wilinski, Runlayer · From 36% to 100%: How Self-Improving Agents Write Their Own Skills, 4:38

    A quirk that cost a retry, a backed-out change or a correction goes into pitfalls.md without asking, and the next session reads it.

  4. “Even though humans and agents may use different services, everything should share the same underlying harness and context.”
    Davis Palmie, Factory · The Software Factory: From Bug Report to Production Code, 12:52

    Claude Code and Codex read the same reference files, and every skill has a Codex version or is registered as needing Claude-only tools.

  5. “Deciding what to build in the software not how to build it.”
    Tereza Tížková, Factory · What It Actually Takes to Build a Software Factory, 21:36
    “The danger is that the engineer never noticed that there was a choice to make.”
    Gabriel Martinez, G2i · Generation Is Cheap, Review Is Expensive: How to Stop Shipping AI Slop, 1:00

    deep-plan: decisions belong to you and facts are the agent's job; each open choice comes to you as a decision, and proposals wait for "apply".

  6. “We don’t need a human to be shepherding this agent through every single step of the life cycle.”
    Ryan Cooke, WorkOS · No, That's Not a Software Factory, 8:03

    deep-plan ends at an explicit Go; once you start long-horizon, every step lists what it depends on and ready steps run in rounds, unattended.

  7. “The agents will often overconfidently claim that they did something when in fact they did not do it.”
    Miguel (Browserbase) and Corby (Microsoft) · Your LLM Judge Is a Confident Liar: Building Better Verifiers, 6:50

    long-horizon writes the auditor's brief before the step runs and sends it unchanged to a fresh-context Auditor; only audited results count as progress.

  8. “Being able to do this type of side-by-side comparison becomes the next evolution of the eval cycle that we see.”
    Hussein, Braintrust · Why Building an Eval Platform Is Harder Than It Looks, 9:52

    arena: parallel attempts judged blind against the same criteria; the strongest becomes the base and the best ideas from the others are grafted onto it.

  9. “This is for expensive things you want to run once when the PR goes up.”
    Dru Knox, Tessl · Harness Engineering: How to Build a Software Factory, 7:23

    A second vendor's model, Codex, reviews every pull request before merge. Once you type /merge, several fresh Codex reviewers review each pull request, confirmed findings are fixed and reviewed again, and it squash-merges after a clean review and passing CI, at the exact commit reviewed.

  10. “We can actually point agents at sessions and see where are the gaps and how people are using our factory.”
    Ryan Cooke, WorkOS · No, That's Not a Software Factory, 17:24

    /refine weekly reads past sessions, proposes rules from repeated corrections and skills from repeated tasks, and the proposals wait for you to apply them.

Beyond what the talks covered

  1. Every pull request, in both directions

    Work done in Claude Code is reviewed by OpenAI's Codex before it merges; work done in Codex is reviewed by Claude (Harness-Firmware #214).

  2. /coordinate

    One session reads another's work, checks its claims at the source and sends a verdict on each recommendation; the two go back and forth until they agree on who does what.

  3. Two tools, one skill set

    Each skill has a Codex version beside its Claude Code version, or is registered as needing Claude-only tools, and CI reports any version that drifts.
