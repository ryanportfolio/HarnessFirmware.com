# Harness Firmware homepage

A standalone homepage built with HTML, CSS, JavaScript, and SVG artwork. No package installation or build step is needed; the preview server requires Node.js.

Run from the repository root:

```sh
node site/server.mjs
```

Open [the local preview](http://127.0.0.1:4348). The server binds to localhost and serves only the `site/` directory; paths that start with a dot (`.env`, `.local/`) are not served. Set `PORT` to use another port. The live site is https://harnessfirmware.com.

The five-stage loop supports manual selection and a deterministic example replay, including a failed check, repair, and retained lesson. Replay is illustrative and does not execute repository actions. Reduced motion shows the complete example immediately. With JavaScript disabled, the default stage and the source disclosure explain the full process.

Third-party assets and their licenses are listed in [PROVENANCE.md](PROVENANCE.md). External links point to the project's source, web creator, and the CoreWise Academy process page.

## Fonts

Four open-licensed faces ship in `assets/fonts/`, each folder with its license. `fonts.css` declares them and sets one token per role; every page links it first and preloads the faces its first screen uses.

- `--font-display`: Lineal at weight 781, for huge type: the hero headline, statements and headings.
- `--font-accent`: Fraunces italic (weight 600, optical size 144, soft 100, wonky on), for the accent words: the hero's rotating word, the pillar words and the answering statement lines.
- `--font-text`: Mona Sans at weight 500, for sub-lines, body text, navigation and buttons. Mona Sans has a Reserved Font Name, so the subset shipped here is renamed Harness Text.
- `--font-mono`: Departure Mono, for typed commands, tags and labels, including the convergence canvas labels.

Huge type is tracked at -0.015em (`--display-track`). Lineal ships as released. The other files are subsets: Latin plus the punctuation and arrows the pages use, with every variable axis the site sets kept. Sources, versions and licenses are in [PROVENANCE.md](PROVENANCE.md).

## Motion hooks

`smooth-scroll.mjs` is the spring smooth-scroll engine, written for this site with no dependencies. Native scrolling moves the document; a fixed content layer trails it through a spring (stiffness 55, damping 15, mass 0.27) and a spacer keeps the document length. With `prefers-reduced-motion: reduce`, every page scrolls natively.

`statement-block.mjs` builds the pinned statements (`.statement-block`: the problem statement and the /long-horizon statement) from three reusable modules, each with its own stylesheet:

- `split-reveal.mjs`: splits a heading into masked lines, words and characters and plays the reveal once.
- `hover-grid.mjs`: a brick-offset grid of square cells with a green light that follows the pointer under the gaps; light and dark variants.
- `pixel-wipe.mjs`: a cols x rows grid of cells that fill in a shuffled (optionally seeded) order as a progress value runs from 0 to 1.

Each statement pins for its panel height plus 150svh of scroll, and its pixel wipe takes the color in `data-wipe` (the section underneath). Pinning, the reveal trigger and the wipe follow the smooth-scroll layer's rendered offset; without the engine the panel pins with `position: sticky` on native scroll. Reduced motion visitors get the static light panel with the whole statement; without scripting the panel is dark, so the transparent header stays legible over it.

`card-row.mjs` builds the command card rows (`.card-row`: Planned and Production-ready) from the same modules. The content box pins for the section plus 150svh of scroll while the next section slides over it; the pillar headline and the three cards reveal once, a dark hover grid and a pointer-following arc on each card frame answer the pointer, and a pixel wipe in the next section's color closes the pin. `card-art.mjs` draws a line animation of each command in the card media. Reduced motion visitors get the static cards with each drawing as a still frame.

`explainer.mjs` plays the explainer section after the hero (`#explainer`, styles in `explainer.css`): nine beats on one line drawing, a wide one above 767px and a tall one at 767px and below, with a caption and an index chip per beat. Each caption is a step label, a headline and its lines, laid out by the beat's `data-layout` (`cross-list`, `pairs`, `example`, `rows`, `sequence`, `checklist`, `statement`, `outcome`), with the markers drawn by CSS. The markup is the end state; the module paints the start of the sequence, then one clock runs 103.8 s once. The headline arrives with its beat and each caption line (`.ex-line`) fades in with a small rise at the moment the drawing shows what it says, on the same clock (`REVEAL` in the module), so Pause freezes the reveals and Replay hides the lines again; without scripting every line shows. Beat 1 draws its three sessions at 1.6 times their resting size, centred, and they ease into their place in the sessions row as the beat ends. At each beat the drawing groups that carry its point stay lit and the others dim to .35 with their labels (the spec's Focus table, `FOCUS` in the module); the finished drawing comes back whole at the end. Stage labels never drop below 10px; where the two-column drawing is narrow, some move and one (`Acceptance checks`) is left out, as on phones. The section title fades out while it is not wholly below the fixed header, whose background is not fully opaque. It starts the first time beat 1's caption is wholly on screen below the fixed site header with at least half of the drawing visible; where the room under the header cannot hold both (landscape phones, short windows), it starts on the caption alone, whole or filling nearly all the room when it is taller (the header height and the caption and drawing sizes are read on load and resize), pauses when the stage leaves the screen entirely, when the tab is hidden or on Pause, resumes from the same point, and stops on the finished drawing, where Pause hides and Replay starts again from the beginning. `#explainer` carries `data-state` (`idle`, `playing`, `paused`, `ended`), `data-beat` (1 to 9) and `data-reading` (the detent's reading position, px). Unlike the other motion modules, it plays the same with `prefers-reduced-motion: reduce`, by the site owner's decision (spec amendment v2); the module does not read the preference. It also adds a scroll detent for mouse-wheel and trackpad scrolling only (spec amendment v9: no lock on touch). A non-passive `wheel` listener, attached only while the explainer is within two viewports of the screen so wheel scrolling elsewhere keeps the browser's fast path, cancels the wheel event that would carry the page across its reading position (the row with the note and the controls, the drawing and the captions together below the header, centred in the room left, with the section title when it fits and otherwise with the title wholly under the header; `#explainer` publishes it as `data-reading`), in either direction, and places the page there with a native instant scroll. For the next 2 s every wheel event is absorbed, in either direction, so the stop is felt even through the smooth-scroll layer's glide; a key, link, scrollbar or script that moves the page ends the pause early. After that wheel scrolling works as usual, and the detent re-arms only once the page moves out of the band where the whole block stays on screen (at least 120 px each way). Nothing else is ever held: touch drags and flicks, taps and clicks, keyboard scrolling, anchor links, incoming fragments, `hashchange` and `popstate`, the scrollbar, and every `window.scrollTo`, `scrollBy` or `scrollIntoView`, instant or smooth, including one made during or right after a held wheel gesture. Whether a wheel event crosses is judged from where the page is, never from where the gesture's earlier input aimed it, so a key, anchor, scrollbar or script scroll made during an unheld gesture is not undone by the next wheel event. The one bound: a scroll that leaves the page at most 8 px past the reading position, right after a notch aimed within 8 px of it, reads as that notch running long, and the next wheel event places the page at the reading position. It works the same with the smooth-scroll layer, which eases to the held position, and under reduced motion. Every box has its size at first paint, and the script changes only opacity, transforms and SVG attributes. Until the module runs, the stage and captions stay hidden, and they appear on their own after 8 s if it never does. Without scripting, the section shows the finished drawing and all nine beats as a list, with no controls; at 767px and below, beat 1 (the problem) comes before the drawing.

## Project creator (/new)

`/new` is the hosted project creator. The page, styles, script, and skill catalog live in `new/`; the server side is `github-creator.mjs`, mounted by `server.mjs` under `/api/harness/github/*` (`status`, `connect`, `callback`, `select`, `disconnect`, `create`).

Without credentials the creator links to the GitHub template page. With a GitHub App configured, a person authorizes once, picks the skills to include, and the server generates the repository from `ryanportfolio/Harness-Firmware`, then commits `.claude/settings.json` overrides and removes the deselected skill directories. Tokens stay in encrypted HttpOnly cookies scoped to `/api/harness/github`; the browser never receives one.

Copy `.env.example` to `.env`, fill it from a GitHub App whose callback and setup URL point at `http://127.0.0.1:4348/api/harness/github/callback` (repository permissions: Administration and Contents, read and write), then start with:

```sh
node --env-file=site/.env site/server.mjs
```

Unit tests: `node --test site/github-creator.test.mjs`.
