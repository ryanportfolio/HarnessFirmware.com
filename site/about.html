The film, chapter by chapter

Seven chapters, six ideas you can use anywhere

Each chapter shows one practice. It works in any repository, with or without the firmware; the last line of each says where Harness Firmware keeps it. Select a chapter to watch it.

  1. On Monday you tell the agent to reset the test database first. On Thursday a new session makes the same mistake. The correction lived in the chat, and the chat ended.

    Use it anywhere: write a correction that matters into a file in the repository, not only into the chat.

    In Harness Firmware: .claude/reference/pitfalls.md ↗

  2. The firmware is plain files: CLAUDE.md and AGENTS.md for the rules, .claude/reference/ for project notes, and .claude/skills/ and .agents/skills/ for workflows.

    Use it anywhere: keep agent instructions under version control, so every clone, machine and sandbox gets the same ones, reviewed like code.

    In Harness Firmware: CLAUDE.md ↗ and AGENTS.md ↗

  3. The next session reads the dated pitfall before it starts, resets the database and finishes the build.

    Use it anywhere: before unfamiliar work, have the agent read the notes for that area, and cite the file and date of any note it acts on, so a stale one is easy to correct.

    In Harness Firmware: the recall skill ↗

  4. Each skill costs one line in the index. Loading every playbook would fill the context. The task calls one skill, and only that one loads.

    Use it anywhere: keep a one-line index of your playbooks and load the full text only when a task calls for it.

    In Harness Firmware: the skill library

  5. The builder marks its work done. A model from another vendor, with fresh context, reviews it and finds two problems. They are fixed and checked again, and you make the call.

    Use it anywhere: have a different model family review the diff, check each finding against the code before changing anything, and keep the merge decision with a person.

    In Harness Firmware: /codex-review ↗

  6. Recall, plan, execute, audit, integrate. Each lap runs faster, and each finding goes back into the repository as a lesson.

    Use it anywhere: when a workflow stumbles, find the cause and fix the rule or skill that allowed it, so the next run starts from the fix.

    In Harness Firmware: /refine ↗ and pitfalls.md

  7. Everything the film showed is kept in one place: your repository.

    Start a repository with the firmware ↗

What you add

Everything lives in files you can read

No service to sign up for. The firmware is Markdown instructions, skills, one session hook and Node scripts that check the setup, committed next to your code.

your-project/
├── CLAUDE.md                rules and routing for Claude Code
├── AGENTS.md                the same boundary for Codex
├── .claude/
│   ├── reference/           architecture, pitfalls, commands, deployment, tech stack, secrets
│   ├── skills/              recall, codex-review, refine and more: one index line each until called
│   ├── hooks/               session-start.sh
│   └── output-styles/       caveman.md, terse replies by default
└── .agents/skills/          the same skills, adapted for Codex

Use it

Three steps to a repository that remembers

  1. 01

    Create the repository

    Use the creator at harnessfirmware.com/new, or choose Use this template on GitHub ↗.

  2. 02

    Open it in your agent

    Claude Code reads CLAUDE.md. Codex reads AGENTS.md. Both share the notes in .claude/reference/.

  3. 03

    Run /init-project

    It detects the stack, asks a short set of questions, fills in the verification and deployment sections and removes skills the project does not need.

Already have a repository? Copy the skills you want from the firmware repository ↗.
